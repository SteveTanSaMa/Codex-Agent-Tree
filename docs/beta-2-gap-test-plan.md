# Beta 2 follow-up qualification / Beta 2 补验方案

基线：`v0.1.0-beta.2`（`2c9a29f`）。本次另建合成任务，不使用历史工程任务或既有团队。先复现/记录契约，再判断是否有实现缺陷；模型叙述不作验收依据。新增覆盖以测试源码和独立结果为准。

| 层 | 场景 | 验收依据 |
| --- | --- | --- |
| 确定性 | 排队内容可见但 ACK 不允许提前消费；pause 保留旧队列，cancel 清除旧队列；实时引导不自动广播 | 实际工具调用/消息状态/Native dispatch 次数，重复排列事件顺序 |
| 确定性 | 累计提醒跨子节点/重启、check-in 不重置预算 | SQLite 事件、提醒游标与 Attempt 数 |
| 实际沙箱 | 固定基线含自包含测试入口；Lead 未提交入口不被复制；依赖测试可读不可写 | 真 Git worktree、真实白名单命令结果与文件哈希 |
| 实际 CLI | 执行中引导与暂停、重启；错误 ID/重发不得派发第二个 Turn | 原生历史、业务 Attempt、终端收据和文件计数 |
| 真实模型 | 两个独立仓库、L2 自测、L3 静态审查、Lead 分别集成并执行跨仓库测试 | 真实代码 diff、失败→通过的测试收据、独立 golden、身份/权限/消息及重启对账 |
| 真实模型 | 工具执行中 steer，同 Turn 遵从；随后立即暂停工具并重启，显式恢复后处理新任务 | Native Turn ID、指令标记、实际命令执行计数、暂停 fence 和绑定 |

真实测试输入为少量合成代码，禁止安装/网络/提交/合并；仅临时测试仓库可写。使用已有隔离提供商配置与匹配 CLI，不修改全局配置，不打印凭据。发布 ZIP 作为真实场景运行代码，检查与 tag 一致。

多仓库场景最多 10 Turn、4 成员、深度 2、并发 3；引导/暂停场景最多 3 Turn、1 成员。两个真实提供商场景合计最多 13 个已准备 Turn；不退款、不清零、无自动真实重试。提醒用于观测，不将 Turn 视为 token/账单硬上限。总墙钟截止分别为 7 和 4 分钟，异常先持久化暂停/中断并保留未知用量，随后仅停止本测试拥有的服务。测试工程及工作树保留用于检查，凭据不写入证据。

边界：少量真实样本无法证明所有提供商、任意竞态或生产级可靠性；提醒阈值仅校验实现逻辑，不以合成任务证明 15/10 分钟适合所有任务。质量/成本对比和恶意仓库安全隔离不在本次范围。

Results are recorded separately. Controlled fixtures, real sandbox/CLI behavior and real provider behavior must remain distinct; passing one layer does not qualify the others.
