# 执行限制调整计划

目标：新团队默认由结构和执行次数约束运行；token 继续核算和告警，仅显式启用时用于准入。

1. **策略与兼容**：新增 `tokenPolicy: observe|enforce`，新建默认为 observe，旧树缺省按 enforce 解释；schema 6 阻止旧实现误读新策略。保留原用量、预留、未知状态与绑定。
2. **执行硬限制**：保留深度、累计 Agent 数、并行 Turn、每节点 Turn；新增树级累计 Turn（默认 100），包含失败/中断和已准备的执行，重启不重置。用尽时不再接纳 spawn/Turn。
3. **token 观测**：observe 不因额度、子分配或其他节点未知用量阻断正常工作；仍记录实际与未结算责任、超阈值事件。enforce 保留原准入语义，不承诺运行中硬上限或账单额度。子分配在 observe 可省略。
4. **CLI/Skill**：增加 `--token-policy`、`--max-total-turns`，统一 view/status 中策略、执行配额和阻塞原因；同步中英文说明及升级说明，取消默认要求模型规划 token 分配。
5. **验收**：覆盖低阈值继续执行、可选硬预算、递归/串行创建/并发/反复唤醒边界、旧状态恢复、幂等、工具身份不可改策略。执行类型/格式/默认/故障/原生及真实安装验收，打包后按现有发布流程推送。
