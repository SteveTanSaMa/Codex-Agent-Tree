# Beta qualification plan

The scoped Beta gates below are completed; see [qualification and limits](beta-validation.md). Alpha.4 remains a separate immutable historical release.

1. Fix reproducible reliability boundaries: durable FIFO across human and Agent messages; preserve late operator usage evidence without unsafe replay.
2. Add an opt-in coding workspace: audited host terminal for Lead within a macOS sandbox, isolated detached Git worktrees for second-level members, read-only third-level access. Enforce restricted file/search/diff/test tools in the host, independently of model instructions.
3. Qualify permissions and recovery: traversal, symlinks, stale identities, canceled work, bounded output, write conflicts, test command selection, restart and migration. No model-supplied shell for descendants.
4. Run a real provider coding workflow: delegate a change, inspect the patch, run a configured test and have Lead review integration. Record native tool calls and resulting repository state; model prose alone is not evidence.
5. Qualify fresh Skill installation, update Chinese/English instructions, run regression/fault/native tests, and publish only the minimal reproducible source and evidence summaries. Tag Beta only after the coding and recovery gates pass.

Default token policy stays observational. Depth, concurrency, lifetime Agents and Turns remain admission limits. Test commands are operator-configured trusted repository code, not an OS security boundary. Native sandbox restrictions still apply to Lead commands. Existing read-only teams retain their original tool catalogs.
